## Goal

An interactive Modern Portfolio Theory trainer — diversification, correlation, the efficient frontier, and the Sharpe ratio — driven by the user's own real historical stock/ETF data, so the intuition is built on real numbers instead of a textbook toy example.

## User Story

As a mid-career academic and solo founder who names "quantitative investing" as both a hobby and an explicit learning goal ("Continue learning quantitative investing and algorithmic trading"), I want to drag real assets around a live risk/return chart built from their actual historical prices, so that I build real intuition for why and how much diversification helps — not just read the formula.

## Scope

### In Scope
- `fetch_data.py`: a runtime script (uses `yfinance`) that pulls 3 years of daily adjusted-close prices for a fixed, diversified 12-ticker basket (large-cap equities across 8 sectors plus a gold ETF and a long-term Treasury ETF for low/negative-correlation examples), computes daily log returns, annualized mean return and volatility per asset, and the full annualized covariance and correlation matrices. Writes `data.js` (`window.PORTFOLIO_DATA = {...}`) for the browser app to load directly — no server, no CORS issue.
- Browser app (`index.html` + `src/app.js`, vanilla JS, classic `<script>` tags, opens directly via `file://`):
  - **Onboarding screen** shown whenever `PORTFOLIO_DATA` is null (the shipped default) — exact instructions to run `python fetch_data.py`.
  - **Explainer tab** — two-asset mixer: pick any two of the 12 assets, drag a 0–100% weight slider, see the portfolio's expected return and volatility recompute live from the *real* covariance between those two assets; a Canvas 2D "risk-return bullet curve" sweeps the full 0–100% range so the user sees the whole curve, not just one point.
  - **Efficient Frontier tab** — all 12 assets: a seeded-random Monte Carlo cloud of long-only portfolios (weights sum to 1, no shorting) plotted as (volatility, return) dots, with the analytical efficient frontier (closed-form two-fund/Lagrangian solution using a from-scratch Gauss-Jordan matrix inverse) drawn on top so the user visually sees the frontier dominate the cloud.
  - **Sharpe & Risk-Free tab** — a risk-free-rate slider (0–6%) recomputes the Sharpe ratio live for the current two-asset mix and for the frontier, and highlights the tangency (max-Sharpe) portfolio found by a 1D search along the precomputed frontier.
  - **Correlation Matrix tab** — a 12×12 color-coded heatmap of real correlations; clicking a cell jumps to the Explainer tab with that pair preselected.
  - **Quiz mode** — "Which of these two portfolios has the better risk-adjusted return?", two random weight combinations generated fresh each round (seeded PRNG, never hardcoded), correct answer always derived live from the real Sharpe ratio; streak/accuracy persisted in `localStorage`.
  - **Optional AI explain button** — direct browser call to the Anthropic API (Claude Haiku) using a session-only key the user types in (never persisted, never sent anywhere but Anthropic), turning the current numbers into a plain-English paragraph; unconditional deterministic-template fallback when no key is supplied or the call fails.
- Tests: `tests/test_fetch_data.py` (pytest, all `yfinance` calls mocked) and `tests/*.spec.js` (Playwright, fixture data injected via `page.addInitScript`, all Anthropic calls mocked via `page.route`).

### Out of Scope
- No brokerage/portfolio-tracking integration (IBKR) — this is a learning tool over a fixed teaching basket, not a live-portfolio dashboard (that's Investment Research Platform/SiliconWatch's job).
- No short-selling / leverage in the frontier math — long-only, weights sum to 1, matches the standard intro-MPT teaching frame.
- No server-side component — everything runs from static files opened directly in a browser plus one local Python script the user runs on demand.
- No persistence of fetched market data beyond the single `data.js` file `fetch_data.py` overwrites each run (no historical accumulation/versioning — this is a teaching tool over the current dataset, not a research journal).

## Tech Stack

- **Language:** Python 3 (`fetch_data.py`) + vanilla HTML/CSS/JS (the app itself)
- **Framework:** None
- **Dependencies:** `yfinance` (Python, runtime-only, listed in `requirements.txt`); Anthropic API is called directly from the browser via `fetch()`, no SDK
- **Runtime requirement:** `python fetch_data.py` once (needs internet + `pip install yfinance`) to generate real data, then open `index.html` directly in any browser — no build step, no dev server

## Data Structure

`data.js` (generated by `fetch_data.py`, loaded via `<script src="data.js"></script>`):

```js
window.PORTFOLIO_DATA = {
  generated_at: "2026-08-09T08:30:00Z",
  years: 3,
  tickers: ["AAPL", "MSFT", "JPM", "JNJ", "XOM", "PG", "HD", "CAT", "NEE", "AMT", "GLD", "TLT"],
  meta: { "AAPL": { name: "Apple Inc.", sector: "Technology" }, ... },
  mean_return: { "AAPL": 0.184, ... },       // annualized, arithmetic mean of daily log returns * 252
  volatility:  { "AAPL": 0.29, ... },        // annualized std dev of daily log returns * sqrt(252)
  cov_matrix:  [[...], ...],                 // annualized covariance, same ticker order as `tickers`
  corr_matrix: [[...], ...]                  // Pearson correlation, same order
};
```

Shipped default `data.js` sets `window.PORTFOLIO_DATA = null` only if not already defined (`if (typeof window.PORTFOLIO_DATA === 'undefined') window.PORTFOLIO_DATA = null;`) — this lets Playwright tests pre-inject a fixture via `addInitScript` without editing the source file, and lets a fresh `fetch_data.py` run overwrite it unconditionally with real data.

`localStorage` (browser, key `portfolioLabState`): `{ quiz: { attempts, correct, streak, bestStreak }, lastPair: ["AAPL","GLD"] }`.

## Testing Strategy

- **Frameworks:** pytest (Python) for `fetch_data.py`; Playwright (`@playwright/test`) for the browser app.
- **Test file locations:** `tests/test_fetch_data.py`; `tests/math.spec.js`, `tests/app.spec.js`.
- **Run commands:** `python -m pytest tests/ -v`; `npx playwright test`.
- **What will be tested:**
  - `fetch_data.py`'s return/volatility/covariance/correlation computation against hand-calculated reference values on a small synthetic price series (no live network — `yfinance.download` mocked).
  - `fetch_data.py` error handling: a failed ticker download is excluded with a warning, not a crash; fewer than 2 successfully-fetched tickers raises a clear error instead of writing broken output.
  - Matrix inverse (`math.js`) correctness on a small known matrix.
  - Global-minimum-variance portfolio weights sum to 1 and its variance is ≤ every sampled Monte Carlo portfolio's variance (dominance property).
  - Two-asset mixer at 0% and 100% weight exactly matches the pure single-asset return/volatility.
  - Efficient frontier points at a given target return dominate (equal-or-better return at equal-or-lower volatility than) the Monte Carlo cloud.
  - Quiz mode: correct/incorrect answer handling and streak logic, using a seeded PRNG so rounds are deterministic in tests.
  - `localStorage` persistence survives a reload.
  - Onboarding screen appears when `PORTFOLIO_DATA` is `null`; main app appears once fixture data is injected.
  - AI explain button: mocked successful response renders correctly; no-key path renders the deterministic fallback and fires zero network requests (asserted via a Playwright route-call counter).
  - XSS safety: a script-injection payload in a fixture ticker's display name renders as inert text (no dialog, no executed script) — verifies `textContent`/`createElement` usage, never `innerHTML` from data.
  - Correlation heatmap cell click correctly preselects that pair on the Explainer tab.
  - Basic responsive check at a narrow (375px) viewport — no horizontal overflow, tabs remain usable.

## Success Criteria

1. All tests pass (zero failures) — both `pytest` and `npx playwright test`.
2. `fetch_data.py` runs correctly against mocked data in tests and would, on a machine with real internet access, produce a valid `data.js` covering all 12 tickers (or a clear degraded-but-valid result if some tickers fail).
3. The two-asset mixer and efficient frontier are mathematically correct — verified by the dominance/boundary-condition tests above, not just "renders without crashing."
4. Quiz mode's correct answers are always derived live from the real (or fixture) covariance data, never hardcoded, and streak/accuracy persist across a reload.
5. The app is honest about its data state — it never fabricates market numbers; without a real `data.js` from `fetch_data.py` it shows the onboarding screen rather than fake data.
