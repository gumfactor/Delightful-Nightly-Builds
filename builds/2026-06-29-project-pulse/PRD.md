# PRD — Project Pulse

## Goal

A CLI + HTML dashboard that eliminates the cognitive overhead of switching between multiple simultaneous projects by maintaining a live activity feed per project, syncing GitHub commits automatically, and generating AI-powered context briefs on demand.

---

## User Story

As a researcher and founder juggling 6+ active projects (neuroscience lab, The Canada List, Kwyeter, teaching, AI builds, investing), I can run `python src/main.py brief canada-list` to get a 3-5 sentence AI-generated brief of what I was doing and what to do next, and `python src/main.py dashboard` to see an HTML dashboard showing which projects have gone quiet and which are active — so I can switch contexts in seconds instead of minutes.

---

## Scope

### In

- Project registry with metadata (name, type, GitHub repos, description, color)
- Automatic GitHub commit sync via `GITHUB_TOKEN`
- Manual activity logging (notes) per project
- AI-generated context brief via Anthropic API (falls back to text summary if key absent)
- Self-contained dark-mode HTML dashboard with:
  - Stacked bar chart of activity per project over last 30 days (Chart.js)
  - Project cards with staleness badges (green/yellow/orange/red)
  - Per-project recent activity list
  - Type filter buttons
- SQLite persistence in `data/projects.db`
- CLI commands: `add`, `list`, `log`, `sync`, `brief`, `dashboard`

### Out

- Mobile app
- External notifications or scheduling
- Integration with Teamwork.com or Coda (credentials not in build environment)
- OAuth or web server
- Importing from other build folders

---

## Tech Stack

- Python 3.8+ (stdlib only at runtime: `sqlite3`, `urllib.request`, `json`, `html`, `argparse`, `pathlib`, `datetime`, `re`)
- Chart.js 4.4.4 via CDN (pinned)
- `pytest` for tests
- SQLite for local persistence
- GitHub REST API via `GITHUB_TOKEN`
- Anthropic Messages API via `ANTHROPIC_API_KEY` (graceful fallback when absent)

## Data Structure

### SQLite Schema

```sql
CREATE TABLE projects (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT UNIQUE NOT NULL,
    slug        TEXT UNIQUE NOT NULL,
    description TEXT NOT NULL DEFAULT '',
    type        TEXT NOT NULL DEFAULT 'code',   -- lab|code|writing|business|personal
    github_repos TEXT NOT NULL DEFAULT '[]',    -- JSON array of "owner/repo"
    status      TEXT NOT NULL DEFAULT 'active', -- active|paused|archived
    color       TEXT NOT NULL DEFAULT '#4a9eff',
    created_at  TEXT NOT NULL,
    updated_at  TEXT NOT NULL
);

CREATE TABLE activity_log (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id  INTEGER NOT NULL REFERENCES projects(id),
    source      TEXT NOT NULL,        -- github|manual
    event_type  TEXT NOT NULL,        -- commit|note
    title       TEXT NOT NULL,
    detail      TEXT NOT NULL DEFAULT '',
    occurred_at TEXT NOT NULL,
    created_at  TEXT NOT NULL,
    UNIQUE(project_id, source, event_type, title)  -- deduplication key
);
```

## Testing Strategy

All tests use `pytest`. Each module is tested in isolation with injectable dependencies and no real network calls (mocked via `unittest.mock.patch`). The database tests use `tmp_path` fixtures for file isolation.

- **test_database.py** — Schema creation, CRUD, deduplication index, slug generation, status filtering
- **test_github_sync.py** — Commit parsing, API response handling, sync with mocked HTTP, deduplication
- **test_briefer.py** — Prompt construction, mocked API success/failure, fallback behavior
- **test_dashboard.py** — HTML structure, XSS safety, staleness calculation, Chart.js CDN, empty states

Run: `python -m pytest tests/ -v`

## Success Criteria

1. `python src/main.py add "Canada List" --type business --repos gumfactor/Delightful-Nightly-Builds` adds a project and `list` shows it
2. `python src/main.py sync` (with `GITHUB_TOKEN` set) pulls commits and reports count per project
3. `python src/main.py brief canada-list` (with `ANTHROPIC_API_KEY` set) prints an AI-generated 3-5 sentence context brief; without the key it prints a text fallback that still contains the project name and recent activity
4. `python src/main.py dashboard` generates a self-contained `dashboard.html` that opens in a browser and shows project cards with staleness badges and a 30-day activity timeline chart
5. All 47 tests pass with zero failures
