> **Build date:** 2026-07-12
> **Category:** D — Creative / Generative
> **Complexity:** Ambitious
> **Day of week:** Sunday

---

## Goal

A local tool that combinatorially generates novel, testable research-question and hypothesis skeletons for forensic/affective neuroscience research, scores them for novelty against everything previously generated, optionally polishes the strongest ones into grant-ready prose with Claude, and keeps a persistent, searchable library of everything produced.

## User Story

As a neuroscience lab director who writes grants and manuscripts around empathy, psychopathy, and stress, I want to generate and browse structured combinations of populations, constructs, outcomes, methods, and theoretical frames from my own research domain, so that I have a running supply of concrete, well-formed candidate research questions to start a grant aim or a new study idea from — instead of staring at a blank page.

## Scope

### In Scope
- A curated, domain-real taxonomy (not generic mock data) of five building-block dimensions seeded directly from the user's named research areas in PROFILE.md: **Population**, **Construct/IV**, **Outcome/DV**, **Method**, **Theoretical Frame** — each entry tagged with compatibility flags so nonsensical combinations (e.g. an fMRI method paired with a population/construct pair that has no plausible neural outcome) are excluded by a rule engine, not randomly generated garbage.
- A deterministic combinatorial generator that samples valid, compatibility-checked combinations and renders each into a filled research-question template ("Does Data driving factor exist? predict Effect in Population, and does Mechanism explain moderate this relationship?") plus a one-sentence rationale and a testability tag (feasible-now / needs-resources / speculative), computed from method+population compatibility rules — this is real logic, not text pasted from an LLM.
- A novelty scorer: token-overlap (Jaccard similarity over normalized key terms) against every question already saved in the local SQLite library, so near-duplicate generations are flagged and can be filtered out before they reach the user.
- Optional Claude (Haiku) polish pass per generated skeleton: turns the skeleton + rationale into a grant-ready paragraph (research question, one-sentence hypothesis, brief justification). Runs only when `ANTHROPIC_API_KEY` is set at runtime; a clearly-labeled deterministic template sentence is always shown as a fallback so the tool is fully usable with zero API key.
- Persistent local SQLite library: every generated batch is saved with a timestamp; each item can be starred, tagged with a free-text project/grant label, marked `used`, and is full-text searchable.
- A self-contained dark-mode HTML viewer (`forge.html`, regenerated by a `render` command) with: a batch generator view, a searchable/filterable library table (by dimension, novelty score, testability, starred, tag), and a per-item detail panel showing the skeleton, rationale, testability tag, novelty score, and the AI-polished paragraph (or fallback) — plus one-click "Copy as Markdown" for pasting into a grant draft.
- CLI commands: `generate` (produce and save a batch), `render` (build/refresh the HTML viewer), `star`, `tag`, `use`, `search`, `list`.
- `requirements.txt` documenting the zero third-party runtime dependency footprint (stdlib only; `urllib.request` for the optional Anthropic call).

### Out of Scope
- No live literature-search integration (PubMed etc. already covered by the 2026-07-02 PubMed Research Radar build) — this tool is about generating new question angles, not retrieving existing papers.
- No multi-user / cloud sync — single local SQLite file, matches every other nightly build's persistence model.
- No fine-tuned relevance model — novelty scoring uses transparent Jaccard token overlap, not a trained classifier; documented as a known limitation.
- No taxonomy editor UI tonight — the five dimension tables live in a single editable JSON seed file (`src/taxonomy.json`) that an advanced user could hand-edit, but no in-app CRUD for taxonomy entries.

## Tech Stack

- **Language:** Python 3.11+
- **Framework:** None
- **Dependencies:** stdlib only (`sqlite3`, `json`, `argparse`, `itertools`, `re`, `html`, `urllib.request`, `hashlib`)

## Data Structure

`src/taxonomy.json` — the seed content (real domain content, not placeholder):
```json
{
  "populations": [{"id": "p1", "label": "...", "tags": ["forensic", "adult"]}],
  "constructs": [{"id": "c1", "label": "...", "tags": ["empathy", "self-report"]}],
  "outcomes": [{"id": "o1", "label": "...", "tags": ["behavioral"]}],
  "methods": [{"id": "m1", "label": "...", "requires_tags": ["neural"], "excludes_tags": []}],
  "frames": [{"id": "f1", "label": "...", "tags": ["allostatic-load"]}]
}
```

SQLite (`output/forge.db`):
```sql
CREATE TABLE questions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  created_at TEXT NOT NULL,
  population TEXT, construct TEXT, outcome TEXT, method TEXT, frame TEXT,
  skeleton TEXT NOT NULL,
  rationale TEXT NOT NULL,
  testability TEXT NOT NULL,
  novelty_score REAL NOT NULL,
  ai_polish TEXT,
  ai_source TEXT NOT NULL,   -- 'claude' | 'template'
  starred INTEGER NOT NULL DEFAULT 0,
  used INTEGER NOT NULL DEFAULT 0,
  tag TEXT
);
```

## Testing Strategy

- **Framework:** pytest
- **Test file location:** `tests/test_*.py`
- **Run command:** `python -m pytest tests/ -v`
- **What will be tested:**
  - Combinatorial generator produces only compatibility-rule-valid combinations (never a method paired with an excluded-tag population/construct)
  - Novelty scorer returns 1.0 for a question compared against an empty library, and a lower score for a near-duplicate already in the library
  - Testability tagging logic (feasible-now / needs-resources / speculative) for known input combinations
  - SQLite persistence: insert, star, tag, mark-used, search round-trip correctly
  - Duplicate-safe schema creation (running `init_db` twice doesn't error or duplicate tables)
  - AI polish: mocked successful Claude response is parsed and stored with `ai_source='claude'`
  - AI polish: no API key set falls back to the deterministic template with `ai_source='template'`
  - AI polish: mocked network/API failure falls back cleanly instead of crashing
  - HTML render escapes user-editable fields (tag) to prevent injection into `forge.html`
  - HTML render includes every saved question and reflects starred/used state
  - CLI `generate` writes the requested count of new rows (respecting compatibility filtering, which may yield fewer than requested if the taxonomy is exhausted)
  - CLI `search` returns only rows containing the query term
  - Full generate → render → search → star → use workflow works end-to-end against a temp DB

## Success Criteria

1. All tests pass (zero failures)
2. `generate --count 10` produces at least 10 compatibility-valid, non-duplicate research question skeletons on a fresh library
3. Running `generate` twice in a row and comparing novelty scores shows the second batch's near-repeats scored measurably lower than genuinely new combinations
4. `render` produces a self-contained `forge.html` that opens via `file://`, with working search/filter and a working "Copy as Markdown" button, verified with Playwright browser automation
5. The tool runs end-to-end with zero API key set (full deterministic fallback path) and the AI-enrichment code path is fully covered by mocked tests
