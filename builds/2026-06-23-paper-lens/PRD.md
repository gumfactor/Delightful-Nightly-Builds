# PRD — Paper Lens

## Goal

Auto-fetch research papers from arXiv, score their relevance to this user's research areas using the Anthropic API, and present them as a searchable dark-mode HTML inbox so the user can stay current with neuroscience and AI literature without manually scanning journals.

## User Story

As a neuroscience researcher and AI practitioner, I run `python src/main.py fetch` each morning to pull the latest papers across my research areas from arXiv. Each paper is scored 1–10 for relevance by Claude and given a plain-English 2-sentence summary. I then run `python src/main.py view` to open a self-contained HTML dashboard sorted by relevance — the papers that actually matter to me float to the top. I can filter by Today / Unread / High Relevance and search by keyword. I mark papers as read in the browser; state persists across sessions.

## Scope

### In Scope
- Fetch papers from arXiv API across 4 user-specific topic queries (affective neuroscience, stress/HPA, psychopathy/empathy, AI agents)
- Deduplicate via arxiv_id so daily runs only add new papers
- Batch analysis via Anthropic API (claude-haiku-4-5-20251001): relevance score (1–10), 2-sentence summary, methodology type, topic label
- SQLite database for persistence (`data/papers.db` inside build folder)
- HTML viewer generated by `view` command: dark mode, search, filter tabs, relevance badges, localStorage read-state
- CLI commands: `fetch`, `view`, `read <arxiv_id>`, `search <query>`, `list`
- Graceful fallback: if no `ANTHROPIC_API_KEY`, assigns relevance=5 and uses truncated abstract as summary

### Out of Scope
- Full-text PDF access
- Email or push notifications
- Sources beyond arXiv (Semantic Scholar, PubMed, etc.)
- Multi-user or cloud storage

## Tech Stack

- Python 3.11, stdlib only at runtime (`sqlite3`, `urllib.request`, `urllib.parse`, `xml.etree.ElementTree`, `json`, `html`, `argparse`, `pathlib`, `datetime`, `os`, `sys`)
- Anthropic API called via `urllib.request` (no `anthropic` package dependency)
- `pytest` for tests

## Data Structure

### SQLite `papers` table
```sql
CREATE TABLE papers (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  arxiv_id       TEXT UNIQUE NOT NULL,
  title          TEXT NOT NULL,
  authors        TEXT NOT NULL,
  abstract       TEXT NOT NULL,
  published_date TEXT NOT NULL,
  fetched_date   TEXT NOT NULL,
  relevance_score INTEGER DEFAULT NULL,
  summary        TEXT DEFAULT NULL,
  methodology    TEXT DEFAULT NULL,
  topic_label    TEXT DEFAULT NULL,
  is_read        INTEGER DEFAULT 0
)
```

## Testing Strategy

All tests use pytest. No HTTP calls in tests — fetcher tests use embedded XML strings; analyzer tests mock the Anthropic response; database tests use in-memory SQLite; renderer tests inspect the generated HTML string.

| Module | Test count | What's covered |
|--------|-----------|----------------|
| fetcher.py | 7 | XML parsing, arxiv_id extraction, author joining, whitespace stripping, empty feed, multi-entry feed, URL construction |
| analyzer.py | 5 | Prompt includes all titles, abstract truncation, valid JSON parsing, malformed fallback, no-API-key defaults |
| database.py | 6 | Table creation, insert+retrieve, duplicate rejection, mark-as-read, search by keyword, empty DB get_papers |
| renderer.py | 7 | DOCTYPE present, title in HTML, relevance score in JSON, XSS-escaped title with `<script>`, empty-state message, search input present, paper count stats |

Minimum: 25 tests, all passing.

## Success Criteria

1. `python src/main.py fetch` retrieves at least 1 paper from arXiv without error and stores it in the database.
2. AI-generated relevance scores and summaries are stored in the database (or fallback defaults are stored if API key absent).
3. `python src/main.py view` produces a well-formed HTML file in `output/` that contains all fetched papers with their relevance scores.
4. Running `fetch` twice does not add duplicate papers — the database contains each arxiv_id only once.
5. All 25+ tests pass with zero failures.
