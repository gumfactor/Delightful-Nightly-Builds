# Manual — Pipeline Pulse

> **Version:** 1.0 (built 2026-07-09)
> **Complexity:** Ambitious

---

## What This Is

Pipeline Pulse is a dashboard for this nightly-build system itself. It reads `builds/index.md` and this repository's own `git` history to answer one question every night before you start reading: how much of what was built has actually landed on `main`, and what's been sitting unreviewed the longest? It found, the first time it was run, that roughly three weeks of nightly builds across 21 branches were still unmerged — this tool exists so that never has to be rediscovered by accident again.

---

## Quick Start

1. From anywhere inside the `Delightful-Nightly-Builds` repo: `python3 builds/2026-07-09-pipeline-pulse/src/main.py`
2. Open the generated file (default: `builds/2026-07-09-pipeline-pulse/output/pipeline_pulse.html`) in any browser.
3. Use the search box to filter the build table, or click a column header to sort.
4. Check the "Needs attention" panel for the oldest unmerged builds, each with a link to the GitHub compare view for that branch.

## How to Use It

### Command-line options

| Flag | Default | Description |
|------|---------|-------------|
| `--repo-path PATH` | current directory (auto-detects the git root) | Path inside the target git repo |
| `--index-path PATH` | `<repo>/builds/index.md` | Path to the catalog file to parse |
| `--owner OWNER` | auto-detected from `git remote get-url origin` | GitHub owner, used only to build compare links |
| `--repo REPO` | auto-detected from `git remote get-url origin` | GitHub repo name, used only to build compare links |
| `--output PATH` | `<this build folder>/output/pipeline_pulse.html` | Where to write the dashboard |
| `--fetch` | off | Run `git fetch origin` before analyzing, to pick up branches created since your last fetch |
| `--no-ai` | off | Skip the Anthropic API call and always use the deterministic "what needs attention" briefing |

Example, fetching the latest branches first:
```
python3 builds/2026-07-09-pipeline-pulse/src/main.py --fetch
```

### Reading the dashboard

- **Hero tiles** — total builds tracked, merged count/%, backlog count/%, oldest unmerged build's age, average rating, and rating coverage.
- **What needs attention** — a one-paragraph briefing (AI-generated if `ANTHROPIC_API_KEY` is set and reachable, otherwise a deterministic summary of the same numbers).
- **Charts** — merged-vs-backlog split, rating trend over time, and builds by category/complexity. If the Chart.js CDN can't load (blocked network, offline use), each chart card shows a text fallback instead of breaking the page — the search and sort features are unaffected either way.
- **Needs attention list** — the oldest unmerged, *actionable* builds (builds marked `discarded`/`aborted` are excluded — they were never expected to merge, so they show a neutral "closed" badge in the table instead of a "backlog" badge).
- **All builds table** — every catalog row, searchable and sortable by clicking any column header.

### Terminal output

Every run also prints a short text summary to the terminal, so you can see the headline numbers without opening a browser:
```
Pipeline Pulse — 28 builds tracked
  Merged:  5 (18%)
  Backlog: 21 (75%)
  Oldest unmerged: "Investment Thesis Journal" (2026-06-14, 25 days)
  Rating coverage: 36% (avg 4.1/10)
```

## Configuration

| Setting | Default | Description |
|---------|---------|-------------|
| `ANTHROPIC_API_KEY` (env var) | unset | When set, the "what needs attention" briefing is generated by Claude Haiku from aggregate stats only (no build titles/notes text is sent). Falls back to a deterministic template on any failure or when unset. |

No other configuration required — everything else is a CLI flag (see above).

## Troubleshooting

| Symptom | Likely Cause | Fix |
|---------|--------------|-----|
| `Error: <path> is not inside a git repository` | Run from outside any git repo, or `--repo-path` points somewhere without a `.git` | Run from inside the repo, or pass the correct `--repo-path` |
| `Error: builds/index.md not found at ...` | `--index-path` wrong, or run against a repo without that file | Pass the correct `--index-path`, or run from `Delightful-Nightly-Builds` |
| Backlog count looks lower than expected | You haven't fetched recently — `list_remote_branches` only sees branches your local git already knows about | Rerun with `--fetch`, or run `git fetch origin` yourself first |
| Charts show "Chart unavailable" text instead of a graph | The Chart.js CDN (`cdn.jsdelivr.net`) couldn't load — a network policy blocked it (this is what happened during tonight's own build/verification) or you're offline | Nothing to fix in the tool — all the numbers are still in the hero tiles and table; the charts will render normally on any connection that can reach the CDN |
| A build's row shows no compare link | That build's folder was found on neither the default branch nor any tracked open branch (e.g. it was merged via a squash/rebase that changed the folder path, or added directly without a branch) | Informational only — the row still shows correct merged/backlog status, just without a clickable link |

## Known Limitations

- Branch discovery only considers remote branches your local git already has refs for; pass `--fetch` (or run `git fetch origin` yourself) for a fully up-to-date view.
- "Merged" is determined purely by whether a build's folder exists on the default branch's tree — it does not check GitHub's PR merge state directly (no reliable, tokenless way to do that from a script). In every case checked during this build, the two agree.
- If two different open branches both happen to add a folder with the same date prefix, only the first one found is linked; this is a rare edge case (see FutureFeatures.md).
