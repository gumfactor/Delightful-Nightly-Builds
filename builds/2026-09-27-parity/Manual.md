# Manual — Parity

> **Version:** 1.0 (built 2026-09-27)
> **Complexity:** Ambitious Project

---

## What This Is

Parity answers one question: is anything falling through the cracks between what's planned in Coda and what's actually being executed in Teamwork.com? It's a read-only, one-way audit — it never writes to either system. Run `parity sync` and it fetches your open Teamwork tasks and your Coda tracking table, matches items by title similarity, and tells you exactly which items are missing from one side, which ones disagree on done/open status, and whether that gap is growing or shrinking each time you check.

---

## Quick Start

1. Copy `config.example.json` to `config.json` and fill in your real Teamwork project IDs and Coda doc/table IDs (see Configuration below).
2. Set three environment variables: `TEAMWORK_DOMAIN` (e.g. `yourcompany.teamwork.com`), `TEAMWORK_API_KEY`, and `CODA_API_KEY`. Never put these in `config.json`.
3. Run `python3 src/main.py sync --config config.json` to fetch both sources and record a sync run.
4. Run `python3 src/main.py render --out dashboard.html` and open `dashboard.html` in any browser.
5. Run `python3 src/main.py sync --config config.json` again on a regular basis (daily, weekly — your call) to build up drift history in the trend chart.

Don't have Teamwork/Coda credentials handy right now? Run `python3 src/main.py sync --config config.example.json --demo` instead — it runs the identical pipeline against bundled sample data with zero network calls, so you can see exactly how the tool behaves before wiring up real credentials.

## How to Use It

### `sync` — fetch and reconcile

```
python3 src/main.py sync --config config.json           # live Teamwork + Coda
python3 src/main.py sync --config config.json --demo    # bundled fixtures, no network
```

Every `sync` call fetches the current state of both systems, matches items by normalized title similarity, classifies each item into one of four buckets, and persists the run to `parity.db` (created automatically next to this build's files). Nothing is ever written back to Teamwork or Coda.

The four buckets:
- **Matched** — item found in both systems, statuses agree.
- **Status Conflicts** — item found in both systems, but one says done and the other says open.
- **Teamwork Only** — an open Teamwork task with no corresponding Coda row.
- **Coda Only** — a Coda row with no corresponding Teamwork task (planned, never turned into real work).

### `history` — see past runs

```
python3 src/main.py history
```

Prints every recorded sync run with its per-bucket counts, oldest first.

### `render` — generate the dashboard

```
python3 src/main.py render --out dashboard.html
```

Builds a single self-contained HTML file (no server, no build step) from the most recent sync run and the full run history. Open it directly in any browser — hero stats up top, a gap-size-over-time chart, and sortable/searchable tables for each non-matched bucket.

### `briefing` — one-paragraph summary

```
python3 src/main.py briefing
```

Prints a short plain-language summary of the latest run. With `ANTHROPIC_API_KEY` set in your environment, this is generated by Claude Haiku from aggregate counts only (never a task title). Without a key, a deterministic template is used instead — no network call is attempted.

## Configuration

| Setting | Default | Description |
|---------|---------|-------------|
| `TEAMWORK_DOMAIN` (env var) | none | Your Teamwork subdomain, e.g. `yourcompany.teamwork.com`. Required for live `sync`. |
| `TEAMWORK_API_KEY` (env var) | none | Your Teamwork.com API token. Required for live `sync`. Never store this in a file. |
| `CODA_API_KEY` (env var) | none | Your Coda API token. Required for live `sync`. Never store this in a file. |
| `ANTHROPIC_API_KEY` (env var) | none | Optional. Enables the AI-generated `briefing`; falls back to a deterministic template when unset. |
| `teamwork.project_ids` (config.json) | — | List of Teamwork project IDs to pull open tasks from. |
| `coda.doc_id` / `coda.table_id` (config.json) | — | The Coda doc and table to read rows from. |
| `coda.title_column` (config.json) | — | The exact column name in your Coda table holding each item's title. |
| `coda.status_column` (config.json) | — | The exact column name holding each item's status. |
| `coda.done_values` (config.json) | — | List of status text values (case-insensitive) that count as "done", e.g. `["Done", "Complete"]`. |
| `match_threshold` (config.json) | `0.5` | Minimum title-similarity score (0–1) for two items to be considered the same. Raise it to reduce false matches; lower it to catch looser title variations. |
| `--db` (CLI flag) | `parity.db` in this build folder | Path to the SQLite database. |

`--demo` mode ignores the `teamwork`/`coda` sections of your config and reads `tests/fixtures/teamwork_tasks.json` / `tests/fixtures/coda_rows.json` instead.

## Troubleshooting

| Symptom | Likely Cause | Fix |
|---------|--------------|-----|
| `Live sync requires TEAMWORK_DOMAIN, TEAMWORK_API_KEY, and CODA_API_KEY` | One or more environment variables isn't set | Export all three before running `sync` without `--demo`, or use `--demo` to try the tool without credentials |
| `Teamwork API returned status 401` | API token is wrong or expired | Regenerate your Teamwork API token from your profile settings and re-export it |
| `Coda API returned status 403` | Token doesn't have access to that doc, or `doc_id`/`table_id` is wrong | Confirm the doc is shared with the account that issued the token, and double-check the IDs from the Coda doc's URL |
| Every item shows up as `teamwork_only`/`coda_only`, nothing matches | `match_threshold` too high for your naming conventions, or `title_column` in config doesn't match your table's actual column name | Lower `match_threshold` in config.json, or verify the column name matches exactly (case-sensitive) |
| Dashboard shows "No sync history yet" | `render` was run before any `sync` | Run `sync` (or `sync --demo`) at least once first |

## Known Limitations

- Matching is based on title text similarity only — two unrelated items with very similar wording could occasionally be matched incorrectly. Always spot-check the "Matched" count against what you expect before trusting the tool blindly on day one.
- Strictly one Teamwork "workspace" of project IDs and one Coda doc/table per sync run — see FutureFeatures.md for multi-doc support.
- No automated alerting yet — you need to run `sync` and check the dashboard yourself, or wire it into your own scheduler.
- Read-only by design. Parity will never create, close, or edit a task or row in either system.
