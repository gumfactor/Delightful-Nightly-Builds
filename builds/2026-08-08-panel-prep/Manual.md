# Manual — Panel Prep

> **Version:** 1.0 (built 2026-08-08)
> **Complexity:** Ambitious

---

## What This Is

Panel Prep is a mock NIH study-section reviewer for your own grant-proposal drafts. Paste or save your Specific Aims / Significance / Innovation / Approach / Rigor & Reproducibility text into a plain text file, and it produces two things: a deterministic completeness/rigor checklist (the same kind of thing a sharp-eyed collaborator would flag before you submit — "you never mention a power analysis," "no blinding or randomization language anywhere") and three differently-tempered reviewer-persona critiques with NIH-style 1–9 scores. Every project you submit is saved as a new version, so you can watch your score actually improve across drafts instead of guessing.

No API key required — the checklist and deterministic scoring are always fully functional. Set `ANTHROPIC_API_KEY` for richer, narrative critique in each persona's voice.

---

## Quick Start

1. Write your draft as a plain text/Markdown file with section headers (see "Draft File Format" below), or just use `sample_proposal.txt` included in this folder to try it out.
2. `python src/main.py submit sample_proposal.txt --project "My R01"`
3. `python src/main.py render "My R01" --out report.html`
4. Open `report.html` in any browser.
5. Revise your draft, `submit` it again under the same `--project` name, and run `python src/main.py history "My R01"` to see your score trend.

## How to Use It

### Draft File Format

Section headers are recognized in any of these three styles (mix and match freely):

```
# Specific Aims
...text...

SIGNIFICANCE
...text...

Innovation: ...text on the same or following lines...
```

Recognized section names (and their aliases): **Specific Aims** (`aims`), **Significance**, **Innovation**, **Approach** (also matches "Research Strategy" or "Methods"), and **Rigor and Reproducibility** (also matches "Rigor & Reproducibility" or bare "Rigor"). If no headers are found at all, the entire file is treated as your Specific Aims section, so a rough single-paragraph draft still produces a (partial) checklist.

### `submit <file> --project NAME`

Parses the file, runs the checklist, runs the three-persona review, and records it as the next version for that project. Prints a terminal summary immediately. Add `--api-key YOUR_KEY` to pass a key directly instead of setting `ANTHROPIC_API_KEY`.

### `list`

Shows every project you've submitted to, with its version count and latest overall Impact score.

### `history <project>`

Shows every version submitted for one project, in order, with its overall Impact score, checklist pass rate, and whether that version used AI or deterministic-only scoring.

### `render <project> [--out report.html]`

Writes a self-contained, dark-mode HTML report for one project: hero stats, the full checklist matrix with pass/fail per item, all three persona cards with their rationale, the resume-of-discussion paragraph, and a score-trend chart across every version submitted so far. Opens directly via `file://` — no server needed. If the Chart.js CDN is unreachable, the chart is replaced automatically with a plain data table.

## Configuration

| Setting | Default | Description |
|---------|---------|-------------|
| `--db` | `panel_prep.db` (next to `src/`) | SQLite database file path |
| `ANTHROPIC_API_KEY` (env var) | unset | When set, each persona's critique is generated by Claude Haiku instead of the deterministic fallback. Only the section text you provide is ever sent — never any other file or data. |
| `--api-key` (submit only) | none | Overrides the `ANTHROPIC_API_KEY` environment variable for a single `submit` call |

## Troubleshooting

| Symptom | Likely Cause | Fix |
|---------|--------------|-----|
| "the file appears to be empty" error on submit | The draft file is blank or whitespace-only | Add actual proposal text before submitting |
| A section you wrote doesn't show up in the checklist | Your header text doesn't match a recognized alias (see Draft File Format) | Rename the header to one of the recognized names, or add a recognized header above that paragraph |
| Every persona scores 9 even though you wrote real content | The checklist looks for specific phrasing (e.g. "power analysis," "randomiz...") — your draft may use different wording | Use `history`/`render` to see exactly which checks failed and adjust language, or treat a 9 as a genuine prompt to add the missing content, not just reword it |
| AI critique never appears even with a key set | The Claude Haiku response was malformed or the network call failed | This is expected, silent-fallback behavior — the deterministic critique is always shown instead so the tool never breaks. Check that `ANTHROPIC_API_KEY` is exported in your shell if you expected the AI path |
| `render` says "no versions submitted yet" | You ran `render` before ever running `submit` for that project name | Run `submit` at least once first |

## Known Limitations

- The checklist only detects whether relevant language is present, not whether the underlying claim is actually correct — a nonsensical "power analysis" sentence still passes that check. Treat a passing checklist as "you remembered to address this," not "this is well-argued."
- NIH's Investigator and Environment scoring criteria are intentionally never estimated — this tool has no access to your CV or facilities description, and guessing would be misleading.
- The section parser is heuristic; unusually formatted drafts (headers embedded mid-sentence, non-standard section names) may split imperfectly. Check the excerpt shown for each section in the HTML report to confirm it captured what you intended.
- This is a single-user, local tool — there is no multi-reviewer or collaborative mode.
