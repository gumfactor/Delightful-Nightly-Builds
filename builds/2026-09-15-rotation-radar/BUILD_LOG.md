[01:05 UTC] First test run caught two real issues before the suite passed:
1. **Syntax**: `src/report.py`'s big HTML template f-string embedded `json.dumps(commentary).replace("</", "<\\/")` directly inside the `{...}` expression, which Python <3.12 rejects (a backslash cannot appear inside an f-string expression part). Fixed by precomputing `commentary_js` as a plain variable before the f-string and referencing the variable instead.
2. **Logic bug in `_cross_sectional_zscores`**: the degenerate-case guard (fewer than 2 valid values, or zero cross-sectional spread) unconditionally returned `0.0` for *every* ticker passed in, including tickers whose input was `None` (no data at all yet). That silently fabricated an RS-Momentum of exactly 100.0 for sectors that had no real momentum data during the warm-up period, instead of correctly propagating `None` so those points get excluded and `InsufficientDataError` can fire when there's truly no valid data. Caught by `test_compute_rotation_insufficient_history_raises` (a 5-day fixture that should raise, but didn't). Fixed by returning `None` for any ticker whose input was already `None`, and `0.0` only for tickers that had a real value but couldn't be z-scored.
