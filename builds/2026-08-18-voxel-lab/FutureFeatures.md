# Future Features — Voxel Lab

Ideas for extending a working, valuable tool — not features required to make tonight's build worth using (those shipped tonight).

1. **Real NIfTI slice loading.** Let the user drop in a de-identified single anonymized NIfTI slice (processed entirely client-side, never uploaded anywhere) so the pipeline visualizations run against a real anatomical image instead of a procedurally-generated ellipse — while keeping the multiple-comparisons simulator on synthetic noise (its whole teaching point depends on there being zero true signal, which real data can't guarantee).
2. **Adjustable HRF parameters.** Expose the double-gamma HRF's shape/scale parameters (currently fixed at Glover 1999 defaults) as sliders, so the HRF/GLM pipeline step can show how a poorly-chosen canonical HRF model mismatches an atypical (e.g. clinical population) hemodynamic response.
3. **Spatial autocorrelation in the noise simulation.** The Multiple Comparisons Lab currently generates fully independent voxel-wise noise. Real fMRI noise is spatially smooth (adjacent voxels are correlated), which is exactly why Bonferroni is overly conservative in practice — adding a configurable spatial smoothness parameter to the noise generator (via a real Gaussian random field, not just a look) would make the Bonferroni-vs-cluster-extent contrast even more concrete and quantitatively accurate.
4. **Export a summary as Markdown/PNG.** A "Copy methods paragraph" button on the MC Lab that turns the current run's parameters and results into a ready-to-paste "Multiple comparisons were corrected using X (alpha=Y)..." methods-section sentence, tying this tool directly to the "write grants and manuscripts" PROFILE.md friction point.
5. **A "which method should I use?" decision guide tab.** A short interactive decision tree (whole-brain vs. ROI analysis? exploratory vs. confirmatory? how many comparisons?) that recommends Bonferroni/FDR/cluster-extent/small-volume-correction based on the user's actual analysis plan, going beyond "here's what each method does" into "here's what you should pick."
6. **Save quiz results across sessions.** A localStorage-backed history of quiz attempts (score, date, which questions were missed) so a student using this repeatedly can track improvement over time, and so the tool could double as an actual TA grading aid for a methods course.
